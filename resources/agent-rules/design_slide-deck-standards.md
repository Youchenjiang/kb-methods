# 技術簡報工程化標準 (Slide Deck Engineering Standards)

> 一段可以貼進 CLAUDE.md / AGENTS.md 的行為規則。

## 可貼上片段

製作或修改技術簡報（如 Open-Slide、PPTX、HTML 簡報）時：
1. **死空間防護（Anti-Deadspace）**：卡片（Card）預設隨內容自然收縮，絕對禁止無節制使用 `height: '100%'` 搭配 `justifyContent: 'space-between'`，避免內容偏少時卡片下半部留下 50% 以上大面積留白。
2. **視覺天平原則（Visual Balance）**：左右欄位密度必須對等。若一側包含高對比終端黑底代碼或截圖，另一側絕不能只有兩行單薄文字，必須以對稱標籤、核心機制解析或資料流卡片補足視覺重量。
3. **資安與技術色彩語意（Semantic Palette）**：
   - 🔴 紅色（Accent/Danger）：專屬於漏洞成因、攻擊 Payload、越界危害、安全警告。嚴禁使用於防禦成功頁。
   - 🟢 綠色（Safe/Success）：專屬於安全修補、防禦措施、驗證成功、狀態碼 200 OK。
   - 🟡 黃色（Warning/Diverge）：專屬於語意分流（Alias vs ScriptAlias）、協定陷阱（500 錯誤）、注意事項。
   - 🔵 藍／青色（Info/Tool）：專屬於基礎工具行為、架構導覽、客觀機制。
   - 🟣 紫色（Escalation/Action）：專屬於權限提權（LPE）、互動式反向連線、深層利用。
4. **拒絕 AI 空洞浮誇用語（No AI Fluff）**：禁止「科學驗證法則」、「親眼見證狀態反轉」、「破案地圖」等宣傳式贅詞。文字必須如同真實資安講師於課堂講解，精準說明技術因果（Why），保留純粹技術事實。
5. **投影字級與簡潔度底線（1080p Standard）**：全螢幕投影環境下，卡片標題 ≥ 38~40px，內文字級 ≥ 30px，終端代碼 ≥ 26px。減少重複贅字，每頁聚焦於一個核心技術機制。
6. **完稿必經審查**：交付任何投影片前，必須自我核對本規範之「完稿自檢清單（Self-Review Checklist）」。

## 完整說明

### 核心心法

**投影片是技術認知的視覺架構，不是文字填空題。**

在 1920×1080 投影幕上，學員只花 3 到 5 秒掃描版面。如果排版上下失衡、顏色指鹿為馬、文字充斥 AI 假大空詞彙，學員會立即失去對講者的技術信任。

---

### 1. 容器盲目撐滿導致的死空間（Dead White Space）與「電梯井陷阱」
- **現象**：
  - **一般死空間**：Card 外框拉滿整個螢幕高度，但卡片內只有 3 行短字，下半部留出 60% 尷尬空白。
  - **電梯井 / 瘦長柱子（The Elevator Shaft Trap）**：在 4 欄或 5 欄 Grid 中，每欄寬度極窄（約 300px），卻硬設 `height: '80%+'` 搭配 `justifyContent: 'space-between'`，導致標題在天花板、結論在腳底，中間留下整整 400px「純色無人區」。
- **根因**：使用了 `height: '100%'` 或 `height: '85%'` 搭配垂直方向的 `justifyContent: 'space-between'`。
- **解法**：
  - 容器與 Card 預設高度為 `auto`（隨內容收縮），改用固定 `gap` 維持自然呼吸感。
  - 多欄布局時，多餘高度應安排「橫向因果推進列（Summary Bar）」或「管線圖（Pipeline）」，絕不縱容空心管子。
  - **機械防線**：交付前執行 `npm run lint:slides` 進行靜態排版掃描。

### 2. 左右欄視覺權重失衡（Visual Weight Imbalance）
- **現象**：左欄放了 1080p 實機截圖或深黑終端代碼區塊（視覺重量極重），右欄卻只有「200 OK 是成功的意思」兩行灰色字，整張投影片視覺向左傾倒。
- **解法**：雙欄排版時，輕側必須配置有質量的技術組件：
  - 關鍵狀態碼徽章（如高對比 Badge）
  - 因果步驟編號清單（1、2、3）
  - 小型對比代碼塊或關鍵參數高亮解析

### 3. 色彩語意混亂（Color Semantic Confusion）
- **現象**：防禦修補頁使用刺眼的紅色邊框；正常檔案讀取與 RCE 執行使用相同的裝飾色；Q&A 隨機塗色。
- **解法**：顏色必須具備機能性，不可作為純裝飾：
  - 攻擊鏈起點（工具行為）→ 靜態青色（Teal）
  - 漏洞與越界漏洞（Exploit/Flaw）→ 警戒紅色（Accent Red）
  - 分流抉擇（靜態讀檔 vs 動態執行）→ 警示黃色（Amber）
  - 成功回顯與安全修補（RCE 成功 / 防禦對策）→ 成功綠色（Green）
### 4. 浮誇虛無的 AI 腔調（AI Hallmark Phrasing）
- **現象**：出現「科學驗證法則：保持其他所有條件不變，只增加標準輸入與 CGI 標頭，親眼見證狀態碼的反轉。」、「現在讓我們展開這場驚心動魄的破案旅程」。
- **解法**：改用工程師與講師的精準陳述：
  - 改為：「GET 請求未包含標準輸入，Shell 遇到 EOF 退出且無輸出標頭（500）；改用 POST 補齊標頭與指令即可回傳結果（200 OK）。」

### 5. 截圖黑邊與黑屏陷阱（The Letterboxing Void Trap）
- **現象**：實機截圖周圍出現大面積純黑邊框（Letterboxing），終端畫面縮得極小，宛如漂浮在黑色無人區。
- **根因**：容器使用了 `background: '#000'` 與 `flex: 1` 撐高，並配合 `objectFit: 'contain'`。當截圖長寬比（如寬螢幕 2.32:1）與容器長寬比（接近 1:1 正方形）衝突時，容器多餘空間全被黑色背景吞噬。
- **解法**：
  - 容器移除 `background: '#000'` 與 `flex: 1` 強制撐高。
  - 容器明確設定圖片之原生比例（如 `aspectRatio: '1920 / 826'` 或 `16 / 9'`），搭配 `objectFit: 'cover'` 與 `width: '100%'`。
  - 欄位垂直空間不足時使用 `justifyContent: 'center'` 置中，確保截圖四邊貼合外框，絕無黑邊浪費。

## 完稿自檢清單 (Self-Review Checklist)

在宣告投影片製作完成前，必須逐項過濾以下問題：

- [ ] **留白檢查**：沒有任何一張卡片存在超過 40% 的無意義空白死空間。
- [ ] **對稱檢查**：圖文並列頁面，文字側的視覺元素重量足以抗衡圖片/終端截圖。
- [ ] **語意檢查**：安全防禦頁面絕無誤用攻擊性紅色；狀態正常/修補皆為綠色。
- [ ] **字級檢查**：正文文字在 1080p 投射下字級是否有 ≥ 30px？標題是否 ≥ 38px？
- [ ] **語氣檢查**：全文是否已掃除「親眼見證」、「科學驗證」、「驚人反轉」等 AI 浮誇贅詞？
- [ ] **深度檢查**：每頁是否講述了「為什麼這樣設計/運作」（Why），而非單純名詞堆疊？
